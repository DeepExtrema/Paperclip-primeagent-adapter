## Compiled Bun: LGPL and relinking

The native Prime executable is generated with `bun build --compile` using **Bun 1.4.0**. Bun's [pinned `LICENSE.md`](../upstream/licenses/bun-1.4.0.LICENSE.md) at [tag commit `34cbb9a40b4bd1bd767d134a7065e66c2432a676`](https://github.com/oven-sh/bun/tree/34cbb9a40b4bd1bd767d134a7065e66c2432a676) says Bun itself is MIT, but **statically links** LGPL-2 JavaScriptCore/WebKit and LGPL-2.1 TinyCC. The complete [GNU Library GPL 2.0](../upstream/licenses/GNU-LGPL-2.0.txt), [GNU Lesser GPL 2.1](../upstream/licenses/GNU-LGPL-2.1.txt) and [pinned TinyCC `COPYING`](../upstream/licenses/tinycc-05f0faf.COPYING) license texts are included here; these are **additional obligations**, not reclassification of the entire executable as MIT. The TinyCC fork used by this Bun source is [`oven-sh/tinycc@05f0fafaa3be31e31d7b4b5c17dc60f62c991171`](https://github.com/oven-sh/tinycc/tree/05f0fafaa3be31e31d7b4b5c17dc60f62c991171) plus [Bun's `tcc.h` patch](https://github.com/oven-sh/bun/tree/34cbb9a40b4bd1bd767d134a7065e66c2432a676/patches/tinycc). [Bun's pinned build definition](https://github.com/oven-sh/bun/blob/34cbb9a40b4bd1bd767d134a7065e66c2432a676/scripts/build/deps/webkit.ts) chooses WebKit commit [`0f966e81b78c84bb23213e391bc679c4ef83e56b`](https://github.com/oven-sh/WebKit/tree/0f966e81b78c84bb23213e391bc679c4ef83e56b).

**A usable rebuild/relink route, not merely a license link:** obtain the complete corresponding Bun source at the above commit, Bun-pinned WebKit and TinyCC sources including modifications, and the public Prime source/patch and catalog pin in [`sources.json`](../upstream/sources.json). Bun's pinned `LICENSE.md` directs a user to clone `oven-sh/WebKit` into Bun's `vendor/WebKit`, run `bun sync-webkit-source` (checks out `WEBKIT_VERSION`) and then `bun run build:local` to compile a Bun executable with modified WebKit and its C++ bindings. Bun's [TinyCC build definition](https://github.com/oven-sh/bun/blob/34cbb9a40b4bd1bd767d134a7065e66c2432a676/scripts/build/deps/tinycc.ts) identifies its source commit and applied patch; modifying that library requires making the modified source available and rebuilding Bun with that modification rather than swapping a dynamically loaded library that does not exist. After obtaining a rebuilt Bun binary whose `--version` remains `1.4.0`, provide its absolute path to this repository's `build-native.mjs --bun` when rebuilding the pinned Prime executable. The build script checks the version, not the Bun binary digest; the resulting Prime executable and complete runtime get new SHA-256 attestations and require a new BFF config and qualification.

For the WebKit route, from a new work directory:

```sh
git clone --no-checkout https://github.com/oven-sh/bun.git bun
git -C bun checkout --detach 34cbb9a40b4bd1bd767d134a7065e66c2432a676
git clone https://github.com/oven-sh/WebKit.git bun/vendor/WebKit
(cd bun && bun sync-webkit-source)
```

Make and retain the recipient's intended library modifications **after** the synchronization (which checks out the pinned WebKit commit); then run `bun run build:local` in the Bun checkout. This route follows Bun's pinned license, and the modified source plus its patch, build scripts and resulting relinkable materials must be made available with the distributed binary under the applicable LGPL option. The public native builder's `--bun` flag then accepts the absolute path to that rebuilt, version-compatible Bun binary; all other documented Prime source pins still apply.

For **binary redistribution**, LGPL static-link conditions require recipients to be able to modify the covered library and relink/rebuild the combined work. Ensure complete corresponding machine-readable covered-library source (including changes), the requisite relinkable application object **or source** and build/install scripts, notices and license terms are actually furnished under the applicable LGPL option (e.g. equivalent source/materials access alongside a downloadable binary). A URL to a moving branch, three MIT notices or an untested statement that the user “could rebuild” is insufficient evidence. The pinned Bun notice also lists further linked libraries (including BoringSSL, libarchive, ICU, codecs, compression libraries) and embedded polyfills with their own terms. The npm/Python-only collector **does not inventory Bun's static libraries or embedded polyfills**; their exact corresponding notices, source/materials and any variant-specific obligations require a separate executable-level audit before release. These four added license/notice files alone do not establish legal completeness or attest that the rebuilt/relinked executable has been exercised.
