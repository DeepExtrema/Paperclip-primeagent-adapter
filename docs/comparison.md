# Comparison: different execution profiles

**Method:** competitors' code was inspected at the exact revisions linked below, not rerun in comparative live tests or benchmarks. Our managed-local column describes source contracts and controlled-broker tests of actual compiled Prime 0.9.7/Python: bounded descendants, compaction, MCP approval/rejection, checkpoint continuation and containment. Provider responses and threshold token usage were fixtures. Live catalog admission and native session acceptance were observed, but the first provider request remained uncertain and the account-owner fence blocked another scope. **This is a prerelease, not live end-to-end qualified.** “Not established in inspected source” is not a claim that a competitor lacks a feature.

| | cblab `prime_local` | sergeevgit1 `prime_remote` | Official Paperclip `pi_local` | This repository `prime_bff` |
| --- | --- | --- | --- | --- |
| Runtime / placement | Real Prime daemon over a WSL Unix socket; resident per-agent root, operator attach/list/steer; explicit per-wake RPC mode. Windows+WSL scope. | Real Prime CLI per wake over SSH, with staged workspace/skills and streamed JSON; `--no-session`. SSH is not a sandbox. | Real **Pi**, not Prime; local execution plus inspected remote-target code and a mature model/config pathway. | Real pinned Prime 0.9.7 ACP binary and Python kernel in local Linux x86_64 containment; neither remote SSH nor resident operator attachment. |
| Credentials / model | Temporary per-invocation Paperclip run-context file is owner-only but deliberately readable by the worker UID; Prime model/provider config can use native defaults. | Scoped host API bridge exists; installed Prime/model selection and remote host security are operator concerns. | Local Pi receives Paperclip token; custom provider registry and optional remote transfer support direct-runtime flexibility. | Host owns subscription refresh/selected authenticated catalog and purpose-bound broker; no provider/general Paperclip credential in contained worker. Exact selected `openai-codex` model; no fallback. |
| Session / effects | Resident root and workspace-first persistence; inspected tests do not prove managed immutable native checkpoints or correlated provider/descendant settlement. | Persistent workspace option, but conversation resume intentionally disabled with `--no-session`; no adapter-level checkpoint authority shown. | Native Pi session checks existing cwd/target and may fresh-start on recognized missing session; structured usage and run-disposition hooks exist. | Strict, scope-bound settled Prime session+kernel/harness checkpoint; uncertain acceptance retains physical exclusion rather than fresh-starting or retrying. Root/child usage is subscription accounting with no invented dollar cost. |
| Practical benefit | Long-lived roots and interactive attach/list are features this profile does not supply. | Remote placement and per-wake asset/skill staging are features this profile does not supply. | Built-in integration, provider choice, model discovery, skills, remote support and cost parsing are real advantages for Pi users. | Narrower managed authority and fail-closed effect contract, at the cost of extra installation/pins and potentially indefinite holds. This is **not** a task-quality or performance ranking. |
