## 0.1.0 — explicit prerelease — 2026-10-09

- Added opt-in `prime_bff` Paperclip external adapter and a standalone loopback BFF that launches the actual patched Prime Agent 0.9.7 native ACP/Python runtime in Linux x86_64 containment. Other agents and defaults remain unchanged.
- Pinned Paperclip, Prime Agent and Prime catalog upstream commits with required reviewed patches; included host migration `0294_prime_runtime`, native model catalog metadata, hash-locked Python kernel/build requirements and native runtime assembly script.
- Public 0.1.0 artifacts are the complete source repository and **both** npm tarballs (adapter and BFF); no compiled Prime/Bun/Python native image or bundled `node_modules` is published. Operators assemble actual native Prime locally with the pinned builder; independently redistributing a compiled image requires additional static-library notices and LGPL rebuild/relink materials.
- Added scoped host subscription authority and authenticated model selection, restricted broker transport, assigned skills/MCP governance and host-mediated issue finalization intent. Initial selected provider/model profile is `openai-codex/gpt-6.1-sol`, not a blanket model-support claim.
- Added private standalone BFF SQLite/WAL receipts, physical workspace writer exclusion and scoped immutable settled native checkpoint handling. Unknown outcomes are retained rather than automatically replayed or migrated into a clean session.
- Exercised actual compiled native ACP/Python execution through a controlled broker: persistent cells, contained file/network probes, governed finish receipt, immutable checkpoint/journal continuation and a greater-than-1-MiB Unicode request. Additional native scenarios enforced child depth 2/total 4 and descendant settlement, explicit/threshold compaction, assigned MCP allow/approval/failure/rejection using original effect status, retained unknown cancellation and contained hostile startup/Git execution. The threshold input was real but its token usage came from a fixture; hostile Python startup did not yield a working kernel.
- Corrected no-owner UUID filtering and subscription OAuth parsing of `OPENAI_API_KEY:null` without accepting API-key credentials. Prime post-run handling and Board hydration preserve unknown Git observations instead of invoking privileged workspace inspection or replacing adapter errors. Ordinary Board runtime-service admission remains supported and shares the Prime physical-admission fence.
- Aligned host and native authenticated Codex catalog discovery with client version `0.162.0`; older versions can silently omit newly supported models. Catalog admission still requires the exact configured model, with no aliasing or fallback. Credential-safe stage diagnostics do not expose upstream bodies or secrets.
- Allowed independently identified, actively owned native child dispatches to overlap. Orphaned, uncertain and approval-pending effects still block new execution; failed reservations cannot leave a false live-owner marker. Two live-dispatch regression cases failed before correction and all 18 broker tests passed afterward. The 69 workspace tests and real PostgreSQL no-owner exclusion coverage also passed.
- Exercised the separate “Prime Agent” UI choice without changing existing agent configurations. Formal approval policy uses the normal `agent-hires`/board flow. Live exact-model catalog admission and native session acceptance succeeded after catalog-version alignment, but the first provider request remained uncertain without a response ID. A separate new scope was refused before provider work by the unresolved account-owner fence. **Live end-to-end execution remains blocked; this publication is explicitly a prerelease.** All uncertain holds remain intact.
- Aligned provider SSE headers with Prime's native subscription client. A disposable real-HTTP/PostgreSQL broker smoke completed correlated SSE settlement and replayed the completed receipt without a second POST; authorization and provider responses were fixtures. The header mismatch is not a proven cause of the live uncertain request, and no live success is claimed for the correction.
- Added source/offline CI jobs, MIT/attribution notices and open-source operator, architecture, security, recovery and development documentation. Source/offline and controlled-broker checks must not be presented as authorized live subscription qualification.
- Qualified GitHub CI on a disposable Ubuntu runner after explicitly permitting the required user namespaces and adding a real bubblewrap preflight. Production containment and the 74-test suite remain unchanged.
- Updated exact Hono and Vitest pins to `4.13.7` and `4.1.11`, respectively, to address the dependency advisories reported during initial publication.
